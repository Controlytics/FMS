## Phase 8 — Integration / System testing (vitest, digilog_test_db, isolated)
**2338 tests. Every file passes IN ISOLATION.** Under full-suite load a variable
subset of `src/e2e/*` files reports 401s (observed 8-14 files / 15-59 tests, different
each run; the same "failing" pair passes on re-run). ROOT CAUSE — **test-harness race,
not a production bug:**
- e2e files share ONE `admin` user; `test-helper.ts:loginAs` globally deactivates that
  user's active sessions on every call (`session.updateMany isActive:false`).
- The auth plugin validates session state (`auth.ts:257` SESSION_INVALID) but caches it
  in a module-singleton 60s `sessionAuthCache`, so whether a still-in-use token is seen
  as valid depends on cache-window timing under the ~2-min full run.
- `fileParallelism:false`, so it is NOT parallel-worker contention; it is shared mutable
  fixture state + a time-boxed cache.
**Impact: cosmetic test flakiness only. Production code is unaffected** (every file green
alone; the auth/session logic is correct — the harness deactivates its own tokens).
RECOMMENDED FIX (separate task, ~40-file refactor): give each e2e file a dedicated user
instead of sharing `admin`, or disable `sessionAuthCache` under NODE_ENV=test for
deterministic behaviour. NOT attempted here — out of scope for the VAPT and risky to rush.

Unit/component/service layers (non-e2e): all green.

### FINDINGS
- **VAPT-1 (MEDIUM) — CSV/formula injection in client-side Excel export.**
  `apps/web/src/lib/excel-export.ts` writes raw `String(cell)` with NO neutralization; used by 11+
  pages (filter-list, audit, deviations, cleaning history, retirement/replacement lists, RFID, QN).
  Backend exports already neutralize via `lib/spreadsheet-safe.ts` (`neutralizeRow`); the web path was
  never wired to it. Input `sanitize.ts` strips HTML only, not leading `= + - @ 	`. A field like
  `=cmd|'/c calc'!A1` / `=HYPERLINK()` / `=IMPORTXML()` exports as a LIVE formula → executes when an
  auditor opens the file. CWE-1236. FIX: apply `neutralizeFormula` in excel-export.ts (mirrors backend).
- **VAPT-2 (LOW) — SUPER_ADMIN omitted from reauth role-lists (real DB).** On digilog_db,
  CREATE_USER/DELETE_USER→['ADMIN'], RESTORE_BACKUP→['ADMIN','PROJECT_LEADER'],
  BULK_UPLOAD_FILTERS→['SUPERVISOR','PROJECT_LEADER] — SUPER_ADMIN in none. So the highest-privilege
  account performs these destructive actions with NO re-auth. Admin-configurable (Config→Action Reauth);
  may be intentional (owner keeps SA exempt from lockout/password-policy per memory) but for §11 the most
  powerful account being least challenged deserves a conscious decision. RECOMMEND: add SUPER_ADMIN to the
  destructive-action lists unless deliberately excepted.
- **VAPT-3 (LOW) — zip-bomb restore returns HTTP 500, not 4xx.** The guard works, but a rejected
  attacker upload is a client error; 500 misclassifies it and hides it among server errors in monitoring.
  FIX: return 400/413 with code INVALID_ZIP for the decompression-limit rejection.
- **VAPT-4 (LOW) — bulk-upload xlsx parsed fully into memory before the 200-row cap.** No
  decompression-ratio guard on the xlsx path (only the 5 MB multipart wire limit). A densely-packed 5 MB
  xlsx can spike parse memory (my 850 KB/50k-row test → +106 MB heap). Bounded, not fatal, but the
  row-cap should ideally reject via a cheap pre-check (e.g. sheet dimension) before full parse.
- **INFO-1 (doc) — `/api/config/password-policy/current` documented "public" but returns 401.** Code
  errs closed (correct); the DOC is stale. No code change; only the login page's own change-password flow
  reads it (authenticated).
