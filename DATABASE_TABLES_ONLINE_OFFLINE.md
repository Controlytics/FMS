# Complete Database Architecture: Online vs Offline

## 1. ONLINE DATABASE (PostgreSQL - apps/api/prisma/schema.prisma)

### A. Asset Management Tables
| Table | Purpose | Online Query |
|---|---|---|
| `asset_templates` | Blueprint for asset types | Used to define fields, telemetry, identifiers |
| `asset_template_versions` | Version history of templates | Track template schema changes |
| `asset_instances` | Actual assets (Filters, Blocks, AHUs) | Main entity registry |
| `asset_relationships` | Connections (CONTAINS, CONNECTED_TO) | Filter→Block→AHU hierarchy |
| `asset_identifiers` | QR/RFID/Barcode mappings | Maps identifier → filterId |

**API Endpoints for Offline Sync:**
```
GET /api/assets/templates?limit=100
GET /api/assets/instances?limit=500
GET /api/assets/identifiers?limit=1000
```

---

### B. Filter Management Tables
| Table | Purpose | Data Cached Offline |
|---|---|---|
| `filter_cleaning_profiles` | Pipeline blueprints (stages + connections) | ✅ Full profile with stages + connections |
| `filter_pipeline_stages` | Individual cleaning stages (PRERINSE, WASH_IN, DRY_IN, etc.) | ✅ Included in profile |
| `filter_pipeline_connections` | Edges between stages (next_stage logic) | ✅ Included in profile |
| `filter_profiles` | Filter type → Profile mapping | ✅ List of profiles |
| `cleaning_cycles` | Actual cleaning operations | ❌ Created offline, synced later |
| `filter_events` | Timeline of each cycle step | ❌ Created offline, synced later |

**API Endpoints:**
```
GET /api/filter-cleaning-profiles?limit=100&status=ACTIVE
GET /api/filter-cleaning-profiles/{id}
GET /api/filters/batch-states  (returns current-state for ALL filters)
GET /api/filters/{id}/current-state
```

---

### C. Configuration & System Tables
| Table | Purpose | Data Cached |
|---|---|---|
| `system_config` | Key-value configs (filter-cleaning-reasons, etc.) | ✅ `cleaning-reasons` |
| `organizations` | Org hierarchy | ❌ Org context only |
| `users` | User accounts | ❌ Current user only |
| `roles` | Permission definitions | ❌ User's role only |
| `role_configs` | UI defaults per role | ❌ Not cached |

**API Endpoints:**
```
GET /api/filters/reasons  (from system_config: 'filter-cleaning-reasons')
```

---

### D. Equipment & Instruments Tables
| Table | Purpose | Data Cached Offline |
|---|---|---|
| `equipment_groups` | Groups of instruments per block | ✅ Full list with instruments |
| `equipment_group_instruments` | Individual instruments (pressure, temp) | ✅ Included in group |

**API Endpoints:**
```
GET /api/equipment-groups
GET /api/equipment-groups?blockId={id}
```

Instrument Details Cached:
- 3 instruments per group (Compressed Air, RO Water, Dryer Temp)
- Each has: min/max range, operating range, unit, least count

### E. PM Schedule Tables
| Table | Purpose | Data Cached |
|---|---|---|

| `pm_executions` | Completed PM tasks | ✅ Due tasks list |

### F. Checklist Tables
| Table | Purpose | Data Cached |
|---|---|---|
| `checklist_profiles` | Checklist templates | ✅ Full profile + questions |
| `checklist_questions` | Individual questions | ✅ Included in profile |

**API Endpoints:**

GET /api/checklist-profiles?limit=100&isActive=true&includeQuestions=true

### G. Audit & Compliance Tables

## 2. OFFLINE DATABASE (SQLite - Mobile Device)

### Generated by Capacitor SQLite Plugin

**Database Name:** `digilog_offline.db` (on device)

#### Schema Definition: [apps/web/src/lib/sqllite-schema.ts](apps/web/src/lib/sqllite-schema.ts)

| Table | Columns | Purpose | Origin |
|---|---|---|---|
| **schema_version** | version, applied_at | Track migration versions | Auto-created |
| **operations** | id, type, filter_id, filter_name, payload, status, created_at, retry_count, error, synced_at | Sync queue for offline operations | Queued locally |
| **filter_state** | filter_id, block_id, current_state, current_cycle, pipeline_graph, pipeline_stages, next_allowed_stages, pending_checklist, answered_checklist_stages, equipment_group, block_change_status, home_block, is_pm_due, pm_reason_key, updated_at | Per-filter state snapshot | Cached from `/api/filters/batch-states` |
| **filters** | id, name, current_lifecycle_state, current_cycle_id, data (JSON), updated_at | Cached filter list | Cached from `/api/assets/instances` |
| **reference_cache** | key (PRIMARY KEY), data (JSON), updated_at, expires_at | Generic API response cache | All 8 API calls stored here |

---

### What Gets Stored in reference_cache?

```
reference_cache TABLE:
├─ key='templates' 
│  └─ data: [AssetTemplate{id, name, fields...}, ...]
├─ key='instances-raw'
│  └─ data: [AssetInstance{id, name, templateId...}, ...]
├─ key='filter-state-{filterId}'
│  └─ data: {currentState, cycle, equipment, pipeline, pending...}
├─ key='cleaning-reasons'
│  └─ data: [Reason{id, code, label}, ...]
├─ key='equipment-groups'
│  └─ data: [EquipmentGroup{name, instruments[3]}, ...]
├─ key='identifier-map'
│  └─ data: {RFID-123: {filterId, filterName}, ...}
├─ key='due-tasks'
│  └─ data: [PmTask{filterId, task, date}, ...]
├─ key='checklist-profiles'
│  └─ data: [ChecklistProfile{name, questions[...]}, ...]
├─ key='cleaning-profiles'
│  └─ data: [FilterCleaningProfile{name, stages, connections}, ...]
└─ key='cleaning-profile-{profileId}'
   └─ data: {full profile detail}
```

## 3. DATA FLOW ARCHITECTURE

### Initialization (App Startup - While Online)

```
┌─ ONLINE (PostgreSQL) ────────────────────────────────────────
│
├─ User logs in
│
├─ Frontend calls syncAllDataForOffline()
│  │
│  ├─ GET /api/assets/templates
│  │  └─ Prisma: SELECT * FROM asset_templates WHERE isActive=true
│  │     └─ Save to reference_cache: key='templates'
│  │
│  ├─ GET /api/assets/instances?limit=500
│  │  └─ Prisma: SELECT * FROM asset_instances (with template join)
│  │     └─ Save to filters table: (id, name, data JSON)
│  │     └─ Save to reference_cache: key='instances-raw'
│  │
│  ├─ GET /api/filters/batch-states
│  │  └─ Prisma: SELECT * FROM cleaning_cycles WHERE filterId IN (...)
│  │     └─ For each filter: return currentState, cycle, equipment
│  │     └─ Save to reference_cache: key='filter-state-{filterId}'
│  │
│  ├─ GET /api/filters/reasons
│  │  └─ Prisma: SELECT configValue FROM system_config 
│  │           WHERE configKey = 'filter-cleaning-reasons'
│  │     └─ Save to reference_cache: key='cleaning-reasons'
│  │
│  ├─ GET /api/equipment-groups
│  │  └─ Prisma: SELECT * FROM equipment_groups 
│  │           WITH equipment_group_instruments
│  │     └─ Save to reference_cache: key='equipment-groups'
│  │
│  ├─ GET /api/assets/identifiers?limit=1000
│  │  └─ Prisma: SELECT * FROM asset_identifiers WITH joins
│  │     └─ Transform to map: {RFID-123: {filterId, filterName}}
│  │     └─ Save to reference_cache: key='identifier-map'
│  │
│  ├─ GET /api/pm-schedules/due
│  │  └─ Prisma: SELECT * FROM pm_executions 
│  │           WHERE status='SCHEDULED' AND date <= TODAY
│  │     └─ Save to reference_cache: key='due-tasks'
│  │
│  ├─ GET /api/checklist-profiles?includeQuestions=true
│  │  └─ Prisma: SELECT * FROM checklist_profiles 
│  │           WITH checklist_questions
│  │     └─ Save to reference_cache: key='checklist-profiles'
│  │
│  └─ GET /api/filter-cleaning-profiles?status=ACTIVE
│     └─ Prisma: SELECT * FROM filter_cleaning_profiles 
│              WITH filter_pipeline_stages + connections
│        └─ For each profile: fetch full detail
│           └─ Save to reference_cache: 
│              key='cleaning-profiles' (list)
│              key='cleaning-profile-{id}' (detail)
│
└─ All data now in SQLite ready for offline use
```

---

### During Offline Operation

```
┌─ OFFLINE (SQLite) ──────────────────────────────────────────
│
├─ Operator scans filter (RFID/barcode)
│  └─ Query reference_cache WHERE key='identifier-map'
│     └─ Result: {filterId, filterName}
│
├─ Load current state
│  └─ Query reference_cache WHERE key='filter-state-{filterId}'
│     └─ Result: {currentState, pipeline, equipment, pending}
│
├─ Show allowed stages
│  └─ From currentState, lookup nextAllowedStages in cache
│
├─ Operator selects action (advance/bypass/submit-checklist)
│  └─ Create operation record in operations table
│     INSERT INTO operations (type, filterId, payload, status='pending')
│
├─ Update filter state optimistically
│  └─ UPDATE filters SET current_lifecycle_state='NEW_STATE'
│  └─ UPDATE reference_cache WHERE key='filter-state-{filterId}'
│
└─ Operation queued for sync
```

---

### Sync Back Online

```
┌─ BACK ONLINE (PostgreSQL) ──────────────────────────────────
│
├─ Sync engine finds pending operations
│  └─ SELECT * FROM operations WHERE status='pending' ORDER BY created_at
│
├─ For each operation:
│  │
│  ├─ Send to backend: POST /api/filters/{filterId}/advance
│  │  └─ Backend creates cleaning_cycles, filter_events
│  │  └─ Audits in audit_trail table
│  │  └─ Response: {success, newState, timestamp}
│  │
│  └─ Update operation status
│     UPDATE operations SET status='synced', synced_at=NOW()
│
├─ After all operations synced
│  └─ Re-fetch all master data (full refresh)
│  └─ Update reference_cache with fresh data
│
└─ Cycle ready for next offline use
```

## 4. TABLE RELATIONSHIPS

### Online → Offline Data Dependencies

```
PostgreSQL (Online)              SQLite (Offline)
────────────────────────────────────────────────────

asset_templates
    ↓ GET /api/assets/templates
    └─→ reference_cache (key='templates')

asset_instances  
    ↓ GET /api/assets/instances
    ├─→ filters table (id, name, data)
    └─→ reference_cache (key='instances-raw')

asset_identifiers
    ↓ GET /api/assets/identifiers
    └─→ reference_cache (key='identifier-map')
        {RFID-123 → {filterId, filterName}}

system_config (filter-cleaning-reasons)
    ↓ GET /api/filters/reasons
    └─→ reference_cache (key='cleaning-reasons')

equipment_groups + equipment_group_instruments
    ↓ GET /api/equipment-groups
    └─→ reference_cache (key='equipment-groups')

filter_cleaning_profiles + stages + connections
    ↓ GET /api/filter-cleaning-profiles
    ├─→ reference_cache (key='cleaning-profiles')
    └─→ reference_cache (key='cleaning-profile-{id}')

cleaning_cycles (for current state)
    ↓ GET /api/filters/batch-states
    └─→ reference_cache (key='filter-state-{filterId}')
        {currentState, cycle, equipment, pipeline}

pm_executions (due)
    ↓ GET /api/pm-schedules/due
    └─→ reference_cache (key='due-tasks')

checklist_profiles + checklist_questions
    ↓ GET /api/checklist-profiles?includeQuestions=true
    └─→ reference_cache (key='checklist-profiles')
```

---

### Offline Data Created (To Be Synced)

```
SQLite (Offline Creation)        PostgreSQL (Online Sync)
────────────────────────────────────────────────────────

operations table (queued)
    ↓ Sync engine replays
    ├─→ POST /api/filters/{id}/start-cycle
    │   └─ Creates: cleaning_cycles, filter_events, audit_trail
    │
    ├─→ POST /api/filters/{id}/advance
    │   └─ Creates: filter_events, audit_trail
    │
    ├─→ POST /api/filters/{id}/submit-checklist
    │   └─ Creates: filter_events, audit_trail
    │
    └─→ POST /api/filters/{id}/bypass
        └─ Creates: filter_events (marked as deviation), audit_trail

filter_state table (snapshots)
    └─ Mirrors current_lifecycle_state from asset_instances
    └─ Syncs via: 
        POST /api/filters/{id}/advance → Updates asset_instances
```

## 5. TTL & Cache Expiration

```
All reference_cache entries:
├─ TTL: 24 hours (1 day)
├─ expires_at: now + 24h
│
└─ Expiry Behavior:
   ├─ Online + expired: REFETCH from API
   ├─ Offline + expired: RETURN STALE (pharma needs it)
   └─ offline_submit: IGNORE_EXPIRY (force use stale data)
```

---

## 6. Sync Conflict Resolution

```
STRATEGY: Server Wins + Client Replay

Server State              Client Offline            Resolution
─────────────────────────────────────────────────────────────

current_state = DRYING   Operator queued:          ✅ Replay works
                         ADVANCE → DRY_OUT          (new state matches)

current_state = READY    Operator queued offline:  ⚠️  Conflict
(profile changed)        ADVANCE (old profile)      Sync fails, notify user

current_state = READY    Operator queued:          ✅ OK
                         START_CYCLE                (new cycle created)

current_state = NULL     Filter deleted on server   ❌ Sync fails
Operator queued online                              Not found error
```

## 7. Query Examples

### Online (PostgreSQL via Prisma)

```typescript
// Get all templates
const templates = await prisma.assetTemplate.findMany({
  where: { isActive: true },
  include: { instances: { select: { id: true } } }
});

// Get current state for ALL filters
const cycles = await prisma.cleaningCycle.findMany({
  where: { status: { not: 'COMPLETED' } },
  include: { equipment: true, profile: { include: { stages: true } } }
});

// Get due PM tasks
const due = await prisma.pmExecution.findMany({
  where: { status: 'SCHEDULED', scheduledDate: { lte: new Date() } }
});
```

### Offline (SQLite)

```sql
-- Check what's cached
SELECT key, LENGTH(data) as size, expires_at 
FROM reference_cache 
WHERE expires_at > datetime('now');

-- Get pending operations
SELECT id, type, filter_name, status, retry_count 
FROM operations 
WHERE status = 'pending' 
ORDER BY created_at ASC;

-- Get current filter state
SELECT json_extract(data, '$.currentState') 
FROM reference_cache 
WHERE key = 'filter-state-{filterId}';
```

## 9. Storage Estimates

| Database | Size | Notes |

| SQLite (tablet, full) | 50-100 MB | After 1 month offline ops queued |
